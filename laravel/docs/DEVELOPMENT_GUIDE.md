# ADR (Architecture Decision Records)

## Назначение

Все архитектурные решения проекта фиксируются в DEVELOPMENT_GUIDE.md в формате ADR (Architecture Decision Record).

Каждое ADR является неизменяемым историческим документом и описывает:

* какое решение принято;
* почему оно принято;
* какие альтернативы рассматривались;
* какие последствия имеет решение.

---

## Формат записи

### ADR-XXX — Название решения

**Дата:** YYYY-MM-DD

### Контекст

Описание проблемы или задачи.

### Принятое решение

Подробное описание выбранного решения.

### Рассмотренные альтернативы

* Вариант A
* Вариант B
* Вариант C

### Причины выбора

Почему было принято именно это решение.

### Последствия

Что изменяется после принятия решения.

---

# Принятые архитектурные решения

## ADR-001 — Единая CMS на Laravel + Filament

**Дата:** 2026-06-27

### Решение

В качестве административной панели используется Filament.

### Причина

Высокая скорость разработки, удобство сопровождения, масштабируемость.

---

## ADR-002 — Единая система хранения изображений

**Дата:** 2026-06-27

### Решение

Все изображения сайта хранятся исключительно через Spatie Media Library.

### Причина

Единый механизм хранения файлов и полная совместимость с Filament.

### Последствия

* Все модели с изображениями реализуют `HasMedia`.
* Используются только `SpatieMediaLibraryFileUpload`.
* Используются только `SpatieMediaLibraryImageColumn`.

---

## ADR-003 — Унифицированные Filament Resources

**Дата:** 2026-06-27

### Решение

Все Filament Resources оформляются по единому шаблону.

### Обязательные элементы

* navigationLabel
* modelLabel
* pluralModelLabel
* navigationGroup
* navigationSort
* navigationIcon
* navigationBadge

---

## ADR-004 — Builder страниц

**Дата:** 2026-06-27

### Решение

Все страницы сайта строятся через единое JSON-поле `pages.blocks`.

### Причина

Максимальная гибкость CMS и возможность изменять структуру страниц без изменения кода.

**Дата:** 2026-06-27

### Решение

Модуль считается завершённым только после выполнения всех требований Definition of Done.

### Обязательные этапы

* Документация

Перед началом разработки любого нового модуля обязательно выполняется этап архитектурного проектирования.

# ADR-009 — AI-First CMS (SEO + GEO)

**Дата:** 2026-06-27

## Контекст

Современные сайты должны быть оптимизированы не только для классических поисковых систем, но и для генеративных ИИ (ChatGPT, Gemini, Claude, Perplexity, AI Overviews и других).

Архитектура проекта должна учитывать требования как SEO, так и GEO (Generative Engine Optimization).

## Принятое решение

Проект разрабатывается по принципу **AI-First CMS**.

При проектировании каждого нового модуля оцениваются три критерия:

1. Удобство для пользователя.
2. Качество поисковой оптимизации (SEO).
3. Качество представления информации для генеративных ИИ (GEO).

## Требования к контенту

Каждая публичная страница должна:

* иметь логичную структуру;
* использовать семантические заголовки;
* состоять из тематических блоков;
* содержать структурированные списки и таблицы там, где это уместно;
* быть удобной как для человека, так и для автоматического анализа.

## Архитектурные требования

Builder является единственным механизмом построения страниц и публикаций.

Каждый Builder-блок отвечает за собственную структуру данных и при необходимости может генерировать соответствующую семантическую разметку.

## Оптимизация

Проект поддерживает несколько уровней оптимизации:

### Уровень сайта

* Organization
* LocalBusiness
* Контактные данные
* Социальные сети
* Sitemap
* Robots

### Уровень страницы

* Meta Title
* Meta Description
* Canonical
* Open Graph
* Twitter Card

### Уровень Builder-блоков

При необходимости отдельные блоки могут формировать специализированную микроразметку (например, FAQ, отзывы или контакты).

## Последствия

* Все новые модули проектируются с учётом SEO и GEO.
* Новые Builder-блоки должны иметь понятную семантическую структуру.
* Контент не должен зависеть от конкретной поисковой системы или ИИ, а должен быть максимально качественным и структурированным.

# Desire House Platform

## Vision

Desire House Platform — это модульная AI-Ready CMS нового поколения для строительных компаний.

Цель проекта — создать систему, которая одинаково удобна:

- владельцу бизнеса;
- контент-менеджеру;
- SEO-специалисту;
- разработчику;
- и искусственному интеллекту.

Платформа должна оставаться простой в использовании, понятной в сопровождении и масштабируемой на протяжении многих лет.

## Mission

Мы не создаём код ради кода.

Мы создаём платформу, которая позволяет строительной компании развиваться без необходимости переписывать сайт при каждом новом требовании.

Каждое архитектурное решение должно уменьшать технический долг и увеличивать возможности системы.

## Engineering Values

1. Простота выше сложности.
2. Архитектура выше временных решений.
3. Документация — часть продукта.
4. Повторное использование лучше копирования.
5. Один стандарт лучше десяти вариантов.
6. Всё должно быть понятно через год.
7. Код должен объяснять своё назначение.
8. AI — такой же потребитель контента, как и человек.
9. Каждый модуль может развиваться независимо.
10. Качество важнее количества.


## ADR-010 — Pragmatic Architecture

#### Архитектура должна помогать разработке, а не тормозить её.

### Если архитектурное решение:

- не приносит пользы в ближайшей перспективе,
- не требуется текущими задачами 
- усложняет разработку без очевидной выгоды,

: то его реализация откладывается до момента, когда она действительно понадобится.

Это полностью соответствует принципу YAGNI (You Aren't Gonna Need It).

## Работа с файлами (Media Library)

### Конфигурация

Для корректной работы Media Library необходимо:

```env
APP_URL=http://localhost:8000
FILESYSTEM_DISK=public
MEDIA_DISK=public
```

После изменения конфигурации выполнять:

```bash
php artisan optimize:clear
```

### Правила

- Все изображения хранятся на диске `public`.
- Для загрузки используется `SpatieMediaLibraryFileUpload`.
- Для отображения в таблицах Filament используется `SpatieMediaLibraryImageColumn`.
- Все изображения выводятся через Media Library (`getFirstMediaUrl()`), без хранения путей в базе данных.
